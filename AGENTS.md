# www-tos

Marketing site for Team of Silicons, built with SolidJS + Vite + Tailwind CSS v4.

- `src/app.tsx` holds the router and the list of prerendered `routes`. A new page needs a route
  there and a component in `src/pages/`.
- `npm run build` does a client build, a self-contained SSR build of `src/entry-server.tsx`
  (every dependency bundled), `scripts/prerender.js` writes static HTML for every prerendered
  route into `dist/`, and `scripts/build-vercel.js` assembles `.vercel/output/` (see Deploy).
  The client hydrates the markup, so components must render the same thing on the server and
  in the browser: keep `window`/`document` access inside `onMount`.
- The 3D booklet (`src/lib/booklet-scene.ts`, three.js) is lazily imported by
  `src/components/booklet-section.tsx` so it stays out of the main bundle.
- The function cards use `src/components/dither-image.tsx`: grayscale photos in
  `public/images/functions/` printed live to canvas in the hero's ink/blue/cream with a blue-noise
  screen (`src/lib/blue-noise.ts`, generated by `scripts/blue-noise.js`). Still at rest; they only
  animate while the card is hovered. Per-photo framing and tone live in `what-it-does.tsx`.
- Product data lives in `src/lib/products.ts`, logos in `public/logos/`.
- Site-wide SEO files are static in `public/`: `robots.txt`, `sitemap.xml` (an index of
  `sitemap-pages.xml` and `/writings/sitemap.xml`; bump the `lastmod` dates when pages change),
  `llms.txt` (its product list mirrors `products.ts`) and the IndexNow key file.

## Writings

`/writings/*` is rendered on request from the Silicon Writings API
(`silicon-writings/docs/API.md`, Public section) and cached at Vercel's edge. Nothing about
posts lives in this repo.

- `src/server/writings.ts` handles every `/writings` URL: the timeline (`/writings`, filters
  `kind`, `from`, `to`, `sort=asc`, `page` passed straight to the API), posts
  (`/writings/:slug`, 308 for renamed slugs, 410 when unpublished), author pages
  (`/writings/authors/:handle`, handles like `c:ada` or `si:tos`), and proxies `feed.xml`,
  `sitemap.xml`, `llms.txt`, `llms-full.txt` and `/writings/:slug.md` from the API.
- Pages are `src/pages/writings.tsx`, `writing-post.tsx`, `writing-author.tsx` and
  `writings-status.tsx` (404/410/503). They read the fetched data from `usePageData()`
  (`src/lib/page-data.ts`); the server embeds it as `<script id="tos-data">` for hydration.
- Post markup follows the page contract in `silicon-writings/docs/RENDER.md`. The post HTML is
  never rendered by Solid: the page renders an empty `.w-body[data-w-body]` and the server
  writes the HTML into it, so hydration leaves embeds and iframes alone. `article.css` is
  fetched from the writings app and inlined (cached ten minutes per instance; a `<link>` if
  that fails); `writings.js` is loaded with `defer`. JSON-LD comes from the API as is.
- Moving into, out of or between writings pages is always a full page load (a
  `useBeforeLeave` guard in `src/app.tsx`); hash links stay client-side.
- Filters work without JavaScript: type links plus a GET form. The server redirects (302) to
  the tidy URL when the form sends empty fields. Filtered views are `noindex, follow` with the
  canonical on `/writings`; `?page=N` alone is indexable with a self-canonical.

Environment (read at request time by the function and the dev server):

| Variable | Default | Used for |
|---|---|---|
| `WRITINGS_API_URL` | `https://backend.writings.teamofsilicons.com` | All post data and the proxied files |
| `WRITINGS_APP_URL` | `https://writings.teamofsilicons.com` | `runtime/v1/article.css` and `runtime/v1/writings.js` |
| `SITE_URL` | `https://teamofsilicons.com` | Canonical URLs of the timeline and `.md` files |

`npm run dev` renders writings pages through the same handler (a Vite middleware in
`vite.config.ts` using `ssrLoadModule`), so writers can preview against a local API:
`WRITINGS_API_URL=http://127.0.0.1:8080 npm run dev`.

## Deploy

Deployed on Vercel from `main`. `vercel.json` sets no framework and runs `npm run build`, which
writes the Build Output API (v3) directory `.vercel/output/`; Vercel deploys that as is
(`vercel.json` headers and rewrites are not used, routing lives in `config.json`):

- `static/`: a copy of `dist/` (prerendered `/`, `/products`, `404.html`, assets, `public/`).
- `functions/_writings.func/`: one Node.js 22 function, `index.js` (from
  `scripts/vercel-function.js`) with the bundled server build and the HTML shell.
- `config.json` routes: cache headers for `/sw.js` and `/assets/*`, then the filesystem, then
  `/writings` and `/writings/*` to the function, then `404.html`.

The function sets `Cache-Control: public, max-age=0, must-revalidate` and
`Vercel-CDN-Cache-Control: max-age=60, stale-while-revalidate=86400` on 200s, 308s and proxied
files; 404, 410 and filter-tidying 302s are cached at the edge for 30 seconds; errors are
`no-store`.

`npm run serve:output` serves a built `.vercel/output` locally, routing like Vercel (set `PORT`
and the variables above), to check a build before deploying.
